Are macros NASM-specific?

The idea exists in almost every assembler, but the syntax belongs to each one. Your %macro, %1 and %%label are NASM’s preprocessor (YASM accepts the same syntax). The same macro in other assemblers looks like this:

Assembler	Define	Argument	Local label
NASM / YASM	%macro name 1 ... %endmacro	%1	%%label
GNU as (GAS)	.macro name arg ... .endm	\arg	\@ counter
MASM	name MACRO arg ... ENDM	arg	LOCAL label
FASM	macro name arg { ... }	arg	local label

So you’d have to rewrite the macro to move this code to another assembler. Directives like global, section, db and equ are also NASM-flavored, and GAS uses .globl, .byte and .equ.

NASM macros can do more, such as a range of argument counts (%macro name 1-2), %0 for the number of arguments, conditionals with %if, and repeats with %rep.

Arguments are separated by commas, and the number of parameters goes on the %macro line. Inside the macro you refer to them as %1, %2 and so on. What you write is pasted in as text.

The parameter count
Declaration	Accepts
%macro m 2	exactly 2 arguments
%macro m 2+	2 arguments; the last one takes everything after the previous comma
%macro m 0-1 0	0 or 1 arguments; the default for %1 is 0
%macro m 1-*	1 or more arguments
Fixed number of arguments

show "register", rbx is a macro with two arguments, a label and a value. It expands %1 to the label and %2 to the value:

nasm
%macro show 2
    push rax
    write 1, %1, ": "
    pop rax
    mov rax, %2
    call print_number
%endmacro

Since the argument is pasted in as text, the value can be anything that is valid after mov rax,. My test passed all three kinds: show "number", 42 printed 42, show "register", rbx printed 7, and show "memory", [counter] printed 99.

The +: letting the last argument contain commas

write 1, "Hi", 10 would normally be three arguments. Declaring the macro with 2+ makes %2 swallow everything after the first comma:

nasm
%macro write 2+
    ...
%%text: db %2

%1 is 1 and %2 is "Hi", 10, which is exactly what db wants. Passing 1 for %1 sent text to stdout, and 2 sent it to stderr. I ran it with stderr hidden to confirm the two lines go to different places.

Optional arguments with defaults
nasm
%macro exit 0-1 0
    mov rax, 60
    mov rdi, %1
    syscall
%endmacro

exit 3 gives exit code 3. A bare exit fills in the default, and I checked that it gives code 0.

Any number of arguments

For 1-* or 0-*, %0 tells you how many arguments were given, and %rotate shifts the list so that %1 is always the next one:

nasm
%macro pushall 1-*
%rep %0              ; repeat once per argument
    push %1
%rotate 1            ; now %1 is the next argument
%endrep
%endmacro

pushall rbx, r12, r13 expanded to push rbx, push r12, push r13. popall rotates the other way (%rotate -1), so it pops in reverse: pop r13, pop r12, pop rbx. I cleared the three registers in between, and the values 1, 2 and 3 came back. argc 10, 20, 30 expanded to mov rax, 3.

Passing a comma inside one argument

Curly braces group something into a single argument. twice {add rax, 5} passes add rax, 5 as one argument, and the macro pastes it twice. The result was 10.

Wrong number of arguments

If you call write 1 where two are required, NASM says:

warning: multi-line macro `write' exists, but not taking 1 parameter
error: parser: instruction expected

That tells you the macro exists but not with that count.

Same name, different counts

You can define two macros with the same name and different parameter counts, and NASM picks by how many arguments you pass. I tested hello (0 arguments, exit code 11) and hello 22 (1 argument, exit code 22).

Things to watch for
Arguments are text, not values. If %1 appears twice, as in twice, whatever you passed runs twice, including any side effects.
Nested macros share registers. show calls write, which uses rdi, rsi and rdx, and print_number and syscall change rcx and r11. In my demo I restored registers in rbx, r12 and r13 so that show couldn’t wipe the values I was checking.
Errors point at the macro call, so when a macro fails, run nasm -E file.asm and look at the expanded text.
